# ADR-2026-11-22：环境检测第二层（代理/抓包、双开、模拟点击）

状态：prototype（代码已接入，`platform.enabled=false` 默认关闭）

## 需求

补齐 libnesec 等商业加固中误报风险较高、需要谨慎设计的检测项：

- 代理 / 抓包（风险 7、20）
- 双开 / 多实例（风险 11）
- 模拟点击 / 无障碍滥用（风险 14）

关联功能编号：DET-06（代理/抓包）、DET-07（双开）、DET-08（模拟点击）。第一层（USB 调试、VPN、虚拟定位、ROM 字段一致性）已于 2026-11-22 以 `yidun_usb_debug` / `yidun_vpn` / `yidun_mock_location` / `yidun_rom` 接入，不在本 ADR 范围。

## 候选和决定

三项均**暂不进入默认启用**。共同问题：单一信号在正常用户设备上出现率高，直接上报会污染事件流并触发误处置。

### 2.1 代理 / 抓包

| 信号 | 误报来源 | 建议权重 |
|---|---|---|
| `http.proxy` / `https.proxy` 系统属性、`Settings.Global.HTTP_PROXY` | 企业设备、开发者、部分运营商配置 | 0.3（仅上下文） |
| 网络接口存在 `tun*` / `ppp*` | VPN 用户（与 VPN 规则重叠） | 0.3 |
| 已安装抓包证书（用户 CA 中含 mitmproxy/Charles/Fiddler/Burp 特征） | 企业 MDM、安全团队 | 0.6 |
| 本地监听端口（8888/8080/9090 等） | 开发机网络、其他应用 | 0.4 |
| 全局 `ProxySelector` / `NetworkSecurityPolicy` 显示用户 CA 被信任 | 同上 | 0.5 |

决定：

- 只用**组合判定**：需要「代理配置或 tun 接口」+「用户 CA 信任抓包证书」同时成立，才以 0.7 上报 `env_proxy`；单独出现只记 0.3 上下文事件，不进入 toast/block。
- 不扫描端口列表作为独立证据：在 Android 上需要额外权限且噪声大。
- 不读取应用私有 CA 配置；只看 `NetworkSecurityPolicy.isCleartextTrafficPermitted` 与系统用户 CA 标志。

### 2.2 双开 / 多实例

| 信号 | 误报来源 | 建议权重 |
|---|---|---|
| `/data/user/<非 0 用户>/<pkg>` 存在同一包名 | 工作资料、访客用户（系统正常功能） | 0.4 |
| 同 UID 下多个进程名 / 多实例目录 | 应用自身多进程 | 0.4 |
| 应用私有目录路径含 `clone`、`parallel`、`virtual` 等字样 | 个别 ROM 的正常路径命名 | 0.3 |
| `ActivityManager.getRunningAppProcesses` 中出现同一包名两次 | 系统/厂商实现差异 | 0.4 |
| 设备上存在已知双开应用包名 | 用户安装但未使用 | 0.3 |

决定：

- 以「进程/UID 级重复」为主证据，目录路径与包名列表只作加权。
- 需要区分工作资料（`UserManager` 返回的 profile 类型）与第三方双开：工作资料单独标记为 `managed_profile`，不计入风险。
- 判定阈值：主证据 + 任一加权信号成立才上报；单独命中不上报。

### 2.3 模拟点击 / 无障碍滥用

| 信号 | 误报来源 | 建议权重 |
|---|---|---|
| 已启用的无障碍服务列表非空 | 合法无障碍用户（视障、自动化测试） | 0.2 |
| 无障碍服务包名命中已知自动化工具 | 用户主动安装 | 0.5 |
| 输入事件注入（`InputManager.injectInputEvent` 调用方非系统） | 需要 native 钩子，误报低但实现重 | 0.7 |
| 同一坐标高频点击、事件时间戳异常 | 需要运行时行为模型，误报高 | 0.2 |

决定：

- **不做**「无障碍服务非空即风险」。只对已知自动化包名 + 事件注入证据组合判定。
- 第一阶段只采集无障碍服务列表作为上下文，不产生风险事件；等行为侧证据落地后再组合。
- 不实现坐标/频率行为模型，除非有明确的样本与误报预算。

## 固定与合规

- 数据来源：`Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES`、`PackageManager`、`ConnectivityManager`、`NetworkSecurityPolicy`、`UserManager`。
- 新增权限：`ACCESS_NETWORK_STATE`（已用于 VPN 检测）。无障碍列表读取不需要额外权限。
- 不引入 kill/exit；响应沿用 `ShieldResponse` 的 log/toast/degrade。
- 规则 ID 预留：`env_proxy`、`env_packet_capture`、`env_clone`、`env_autotap`；接入时同步更新 `knownDetectionRule`（客户端 + 后端）与规则包版本门控。

## 验证

晋级条件（candidate → prototype）：

1. 正负样本各 ≥ 20 台/次：开发机代理、企业 MDM、VPN 用户、工作资料、合法无障碍用户、已知双开用户。
2. 误报率目标：单规则 < 1%，组合规则 < 0.2%。
3. 任何规则不得在无对应信号时产生事件；组合规则必须记录全部命中分量到 evidence。
4. 设备矩阵至少覆盖 Android 11 / 13 / 14 与一个厂商 ROM。

未满足以上条件前保持 candidate，不进入默认规则包。

## 实现状态（2026-11-22）

- 规则已接入：`env_proxy`、`env_packet_capture`、`env_clone`、`env_autotap`、`env_screen_share`。
- 由 `yidun.platform.enabled` 控制，默认 false；context 事件只记录，不进 toast/block。
- 设备测试（Pixel 5 / API 37 模拟器）在开启候选层后无风险级误报；修复了 `http_proxy=:0` 被误判为代理配置的问题。
- 晋级仍需满足本文“验证”节的样本、误报率和设备矩阵条件。
