# ADR-0001：P0 密码后端与测试依赖

状态：P0 已采用；生产选型待 P1 复核

## 需求

关联功能：P0-05 容器 v2 双端编解码、P0-06 策略/清单格式。
构建侧需要 AES-256-GCM、HKDF-SHA-256、Ed25519；宿主测试需要独立读取同一组向量；Android 运行时需要可移植的密码后端，但不把构建/测试依赖带入客户端。

## 候选和决定

| 用途 | 决定 | 理由 |
|---|---|---|
| Python 构建侧 | `cryptography` 50.0.1 | 已安装；AES-GCM/HKDF/Ed25519 齐全；用于生成向量与策略/清单测试 |
| 宿主 C++ 向量测试 | OpenSSL 3.5.0（Homebrew） | 只做独立解码验证，不进入 APK；避免测试代码与构建侧共用同一实现 |
| Android 运行时 | 候选 BoringSSL，P1 复核 | 设计 §18 的候选；需固定提交、许可与 ABI 验证后再定 |
| 规则引擎 | YARA，P3 复核 | 当前未引入 |

## 后果

- Python 与 C++ 两侧使用不同密码实现，可以交叉发现格式/AAD/nonce 错误。
- OpenSSL 仅限 `backend/tests/native`，不得链接到 `:shield` 或任何客户端产物。
- `cryptography` 与 OpenSSL 版本先登记为 candidate，发布前必须固定完整版本、校验和、许可证与 NOTICE。
- Android 端密码后端在 P1 前保持空缺；`core.cpp` 不实现解密，避免形成未验证的临时密码层。

## 验证

- `backend/tests/vectors/container/v2/{single,multi}` 由 Python 生成，C++ 读取器独立解密并比对 SHA-256。
- `python3 -m unittest discover -s backend/tests/pipeline` 覆盖容器、策略、清单正负例。
- 验证日期：2026-11-12；设备：Pixel 5 / API 30（仪器测试）。
- 限制：P0 清单规范化是排序 JSON 子集，不是完整 RFC 8785 JCS；P1 冻结前替换并补向量。
