## P1-D3：dup 生命周期

原实现把 memfd fd 直接返回业务，同时由 `ParcelFileDescriptor` 持有同一个 fd。
业务 `close` 原 fd 后，PFD 变成 `EBADF`；`dup` 出的新 fd 也不在 Java 状态表里，
关闭时无法回写。

修复：

| 位置 | 内容 |
|---|---|
| `ShieldNativeIo.open` | PFD 私有一份 memfd；业务拿到 `ParcelFileDescriptor.dup(...).detachFd()` 的独立 fd |
| `ShieldNativeIo` | `State.refs` 引用计数；`rememberDup/forgetDup`；最后一次 close 才 sync + 关闭私有 PFD |
| `file_hooks.cpp` | 新增 `dup/dup2/dup3` hook；shadow fd 的 dup 结果继续标记为 shadow，`dup2` 覆盖目标时先注销旧状态 |

设备探针 `nativeProbeDupWrite`：open → dup → 通过 dup fd 写 `D2XYZ6` →
先 close 原 fd、再 close dup fd → Java 侧读回。结果：

```text
dupErr=0 javaDup=D2XYZ6
```

## P1-D5：故障用例

新增 `ShieldChunkStoreTest`：

- `truncatedFileIsRejected`：FMF2 截断后打开必须失败；
- `staleTempFromCrashIsDiscarded`：残留 `.fmf2.tmp` 被丢弃，原文件内容不变，后续写入正常；
- `secondWritableOpenIsRejectedThenReopens`：同进程第二个写打开被文件锁拒绝，关闭后可重开；
- `renamedFileKeepsContent`：加密文件 `ATOMIC_MOVE` 重命名后可正常解密；
- 原有 shrink/grow、nonce 轮换、篡改 chunk/header、legacy 迁移用例继续通过。

`ShieldPolicyPatternTest` 增加排除优先：

```text
files/harness.txt      -> 加密
databases/harness.db   -> 排除
cache/entry            -> 排除
```

Demo 增加 SQLite 读回探针（`databases/harness.db` 不在加密策略内），设备结果：

```text
readback ... mmap=true sqlite=true
```

## 限制

- `firstFrameMs` 是 post 近似值，不是 SurfaceFlinger 统计；
- 后续 journal 轮次已为 FMF2 补提交日志与打开时恢复；日志引用完整临时镜像，非增量 WAL，周期回写窗口仍在；
- `dup` 只覆盖 libc `dup/dup2/dup3`，`fcntl(F_DUPFD)` 和 `SCM_RIGHTS` 传递未跟踪；
- SQLite 验证走系统 SQLite 路径，用来确认排除项直通，不声明业务 sqlite 加密。
