# 2026-11-21 P2：split APK / AAB 支持

## 范围

让保护流水线接受 base + split 的多 APK 输入，并把 AAB 转成可保护的
universal APK。业务 DEX 与 native 库可以分布在 base 或 split 中；保护后
输出同签名的 APK 集合，S8 gate 校验 split 哈希。

## 实现

| 位置 | 内容 |
|---|---|
| `cli.py` | `--split` 可重复；`--bundletool` 指定 executable 或 jar |
| `intake.py` | 校验 split 的 package/versionCode、split 名唯一、证书一致、DEX 有效、硬加固标记 |
| `inventory.py` | 合并 base/split 的 DEX 与 lib，记录 `source` |
| `dex_stage.py` | 跨 APK 读取 DEX；split DEX 以 `<split>/classes.dex` 命名进入 FDX2 |
| `protect.py` | 跨 base/split 裁符号、加密内存库、删除 split 中的 DEX/已加密 so；split 同模式对齐/签名 |
| `pipeline.py` | `.aab` 支持 `--aab-mode universal` 与 `--aab-mode split`（需 `--device-spec`）；AAB 允许未签名输入 |
| `tools.py` | bundletool 解析、`--aapt2` 传递、universal.apk 提取 |
| `gate.py` | 校验签名清单中的 `splits[]` 文件、大小与 SHA-256；缺失/多余均失败 |
| `formats/axml.py` | 修复 string pool 4 字节对齐，AAB universal 的二进制 manifest 可正确回写 |

### 输出布局

```text
out/protected.apk
out/protected.apk.protect.json
out/protected.apk.splits.json
out/protected_splits/<split>.apk
```

`protected.apk` 的 `assets/shield/manifest.sig` payload 增加：

```json
"splits": [{"name": "config.arm64_v8a", "file": "split_signed.apk",
            "size": 8538, "sha256": "..."}]
```

### 使用

```bash
python -m forgemirror.cli protect \
  --apk base.apk \
  --split split_config.arm64_v8a.apk \
  --split split_config.xxhdpi.apk \
  --in-memory-libs libdemo.so,libdemo2.so \
  --signing-mode hsm

adb install-multiple protected.apk protected_splits/split_config.arm64_v8a.apk
```

AAB universal：

```bash
python -m forgemirror.cli protect \
  --apk app.aab --bundletool /path/to/bundletool \
  --out artifacts/app --signing-mode hsm
```

AAB split（默认模式，按 device spec 生成 config splits）：

```bash
python -m forgemirror.cli protect \
  --apk app.aab --bundletool /path/to/bundletool \
  --aab-mode split --device-spec device-spec.json \
  --out artifacts/app --signing-mode hsm

adb install-multiple protected.apk protected_splits/*.apk
```

多设备规格批量生成（`--device-spec` 可重复，必须 AAB + split 模式）：

```bash
python -m forgemirror.cli protect \
  --apk app.aab --bundletool /path/to/bundletool \
  --aab-mode split \
  --device-spec spec-api30-arm64.json \
  --device-spec spec-api26-v7a.json \
  --out artifacts/app-batch \
  --signing-mode hsm
```

```text
artifacts/app-batch/
  batch.json
  00_spec-api30-arm64/  intake/inventory/container/protected.apk/protected_splits/gate.json
  01_spec-api26-v7a/    同上
```

每个子集独立跑 S0–S8；`batch.json` 记录 spec、输出目录、protect 元数据和 gate 结果。
单 `--device-spec` 或普通 APK 仍保持原输出布局。

### split 中的壳库去重

base/config split 原始输入可能各自带 `libshield_*`。保护时把变换后的壳库统一注入
base，并从所有 split 删除同名壳库（含 `libshield_core.so`），避免 split 残留
未变换/明文核心库。

## 限制

1. AAB 支持 `--mode=universal` 与 `--mode=default`（`--aab-mode split` +
   `--device-spec`，可重复批量）；每个 spec 独立跑完整 S0–S8，容器/DEX 会重复构建，
   尚未做跨 spec 共享优化。
2. split 的 `AndroidManifest.xml` 不改写；只改写 base manifest。依赖 Play/installer
   保持 base 与 split 的版本、签名一致。
3. split 的运行时完整性未在 `ShieldIntegrity` 中校验；目前由构建期 S8 gate 校验
   签名清单中的哈希。运行时只校验 base 内 artifacts。
4. 动态功能模块的按需下载、conditional delivery、asset pack 未覆盖；当前把
   feature split 的 DEX 直接并入容器并删除原 DEX。
5. `customer_local` 模式下 split 只对齐不签名，需要客户用同一证书签署整个集合。
6. split 输入中的 `libshield_*` 会被删除并统一由 base 提供；若产品策略要求按 ABI
   拆壳库，需要后续把注入目标改为对应 config split。
7. `build` 子命令仍只接受单个 `--device-spec`；批量能力目前只在 `protect` 端到端命令提供。
7. AXML 修复只保证 round-trip 与 `aapt2` 解析；复杂 manifest 的未知 chunk 仍按
   原始字节保留。
