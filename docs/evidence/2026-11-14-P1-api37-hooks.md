# 2026-11-14 P1：API 37 hook 兼容与 ClassLoader 库搜索路径

## 范围

在 Android 16（API 37，arm64 模拟器）上回归受保护应用时，出现只在加载
`libshield_hook.so` 后触发的 `RenderThread` SIGSEGV，栈固定在
`libEGL.so egl_display_t::initialize -> strstr`。同时，默认保护在 API 37 上
报 `UnsatisfiedLinkError: library "libdemo2.so" not found`。本项修复这两类
平台兼容问题，并保持 API 30 与 v2rayNG 回归。

## 根因与修复

| 问题 | 根因 | 修复 |
|---|---|---|
| EGL SIGSEGV | 公共 `dlopen` 被 ShadowHook inline hook 后，API 37 的 libEGL/驱动加载路径异常 | 改为 hook bionic 内部 `__loader_dlopen`，保留公共 `dlopen` 作为旧平台 fallback |
| 参数错位 | `__loader_dlopen(name, flags, caller_addr)` 是 3 参；按 2 参调用时 x2 为垃圾，linker 用错误 caller 解析 namespace | 新增 `loader_dlopen_t`，原样透传 `caller_addr` |
| 重复 hook | `libdl.so`、`/system/lib64/libdl.so`、apex 路径指向同一 ELF，旧实现逐个 `hook_sym_name` 叠代理 | 用 `dlopen(RTLD_NOLOAD)+dlsym` 解析地址并按唯一地址 hook 一次 |
| dlopen 内 JNI | 每个 dlopen 都回调 Java 查询加密资产，API 37 上触发驱动加载异常 | bootstrap 时缓存加密库名，未知库直接透传；仅命中名单才走 JNI |
| 依赖解析失败 | `ShieldClassLoader` 的 `librarySearchPath` 为 null，API 37 建空 namespace，`libdemo.so` 找不到 `DT_NEEDED libdemo2.so` | 传入与 app loader 一致的 `nativeLibraryDir + apk!/lib/<abi>` 搜索路径 |

## 验证

API 37 arm64 模拟器（默认保护，无内存库）：

```text
ShieldHook: hook __loader_dlopen at ... ok
ShieldRuntime: native file hooks status=0
MainActivity: probe ... native=T2XYZ6 java=T2XYZ6 ...
             dependency=7 dlopen=7 lockErr=0 overload=11/12
```

API 37 加密库（`--in-memory-libs libdemo.so,libdemo2.so`）：

```text
FMElf: loaded libdemo2.so base=... size=20480
FMElf: loaded libdemo.so base=... size=438272
ShieldHook: dlopen redirect libdemo2.so
MainActivity: probe ... dependency=7 dlopen=7 lockErr=0 overload=11/12
```

API 30 物理设备（Pixel 5）默认保护与内存库均通过同一组探针；v2rayNG 2.4.0
默认保护 `bootstrap ok state=4`，MMKV 初始化与 mmap 正常。

测试：Shield JVM 39 项、Python pipeline 68 项、Go 测试通过。

## 限制

1. `__loader_dlopen` 是 bionic 内部符号，非 NDK 稳定 ABI；已保留公共
   `dlopen` fallback，但其他 linker 实现（非 bionic）需另测。
2. 加密库名缓存上限 64 条、每条 128 字节；超出部分不参与 dlopen 重定向。
3. 本次 API 37 验证为 arm64 模拟器；ARM32 已在 Pixel 5/API 30 用
   `armeabi-v7a` 安装验证通过；x86/x86_64 仍未真机覆盖。
4. `librarySearchPath` 会暴露 APK `lib/` 目录给容器 ClassLoader，未加密库
   仍按原有 `lib/` 语义加载；属于预期行为，但与“全量加密”目标需在产物策略区分。
