# 2026-11-13 P3：事件队列与批量上报

## 范围

壳内安全事件记录、FMF1 加密本地队列、批量上传；Go API 入库与查询；前端安全事件面板；覆盖文件追加写。

## 实现

| 模块 | 内容 |
|---|---|
| `ShieldEvents.java` | 事件入队、按 `rule_id + evidence_hash` 去重、200 条上限、FMF1 加密落盘、单线程批量上传、服务端接受后才出队 |
| `ShieldRuntime.java` | 规则扫描命中后写入 `rule_hit` 事件（confidence 0.7，payload 含 `entry` / `sha256`） |
| `ShieldRules.java` | `Match {ruleId, entry, sha256}`，命中返回条目与摘要 |
| `ShieldConfig.java` | 新增 `event_url` / `event_token` |
| `protect.py` / `cli.py` | 注入事件配置，`--event-url` / `--event-token`；cleartext 判定同时考虑 `auth_url` 与 `event_url` |
| `0003_events.sql` / `store/events.go` | `security_events` 表、批量插入、按 id 倒序查询 |
| `api.go` | `POST /api/v1/events`（`X-Client-Token`）、`GET /api/v1/events?limit=` |
| `frontend/src/App.vue` | 安全事件面板（时间 / 应用 / 类型 / 规则 / 置信度） |
| `ShieldFiles.java` | `MODE_APPEND`：先解密已有 FMF1 内容再追加 |
| `HarnessStorage.java` | 追加写与读回校验（`append=true`） |

## 验证

### AXML 属性排序修复（关键问题）

症状：改写后的 manifest 中 `android:usesCleartextTraffic="true"`，`aapt2 dump` 可正常读出，但运行时
`NetworkSecurityPolicy.isCleartextTrafficPermitted()` 仍为 false，事件上传被
`Cleartext HTTP traffic to 127.0.0.1 not permitted` 拦截。

根因：`AssetManager` 按资源 ID 解析 `android:` 属性，属性必须按资源 ID 升序排列；原实现把新属性追加到
`<application>` 属性列表末尾，框架解析不到。对比 Gradle manifest merger 产出的属性顺序可确认这一点。

修复：`axml.serialize` 在写出 `START_ELEMENT` 前按资源 ID 稳定升序排序，非资源属性（ID 为 0）排最后。
新增回归测试 `test_attributes_sorted_by_resource_id`。

## 限制

1. 事件类型目前只有 `rule_hit`；响应分级、阻断/告警动作未接入。
2. `device_id` 仍为空，未与设备注册/授权绑定。
3. 队列只做去重与条数上限，没有容量、过期与磁盘配额策略。
4. 上传通道为开发期 HTTP + 静态 `X-Client-Token`；生产需要 mTLS 或请求签名与重放保护。
5. 规则版本门控与热更新未实现。
