# 2026-11-13 P1-D 透明文件保护执行记录

## 范围

SPK1 策略包加载与匹配、FMF1 加密文件信封、SharedPreferences 与普通文件透明读写、排除项直通、篡改拒绝、跨重启持久。

## 实现

| 模块 | 文件 | 说明 |
|---|---|---|
| 策略包 | `ShieldPolicy.java` | SPK1 验签（ECDSA raw r‖s→DER / Ed25519 fallback）、HKDF 解密、`*`/`**`/`?` 匹配、排除优先 |
| 密码原语 | `ShieldCrypto.java` | HKDF-SHA256、AES-GCM、FMF1 信封（magic+version+alg+nonce+AAD 绑定） |
| SharedPreferences | `ShieldSharedPreferences.java` | 全类型读写、StringSet、commit/apply、监听器、原子写（tmp+fsync+rename） |
| 普通文件 | `ShieldFiles.java` | 输出缓冲后原子加密落盘；输入经 pipe 返回真 `FileInputStream`；遗留明文直读 |
| 调用点门面 | `ShieldStorage.java`（壳内公开）+ harness `ShieldStorageFacade` | 设计 §16.4 的"构建期调用点适配"的运行期形态；通用 DEX 改写在 S5/S6 |
| 密钥隔离 | 文件密钥 = `HKDF(K_content, build_id, "FM/files/v1")` | 与 DEX/策略密钥域分离 |
| Python 侧 | `policy.py` 支持 `ecdsa-p256-sha256-raw` | 与清单相同的算法协商 |

策略包注入 `assets/shield/policy.pkg` 并纳入清单签名产物（14 项）。

## 设备验证（Pixel 5 / API 30，12 DEX 受保护包）

### 密文落盘

```text
shared_prefs/harness_prefs.xml: 46 4d 46 31 01 00 01 00 ...（FMF1 密文，78 B）
files/harness.txt:               46 4d 46 31 01 00 01 00 ...（FMF1 密文，58 B）
files/harness_plain.txt:         "plain 1794..."（直连流，未拦截，保持明文 = 记录的边界）
```

### 透明读回（重启后）

UI：`readback prefs=true counter=2 file=true` —— prefs 计数跨重启递增，覆盖文件读回原文，业务完全无感。

### 篡改拒绝

改坏 prefs 密文 4 字节后重启：

```text
ShieldPrefs: prefs load rejected for harness_prefs.xml: AEADBadTagException
```

应用不崩溃，prefs 从空状态重建（counter 重置 1），文件读回正常。

## 边界与限制

1. **覆盖面 = 调用点适配**：只拦截经 `ShieldStorage` 门面的调用。直连 `new FileOutputStream(File)`、`getDir`、`getExternalFilesDir`、mmap、直接 syscall 均未覆盖（设计允许：P1-D 验证语义，PLT Hook 全量拦截是 P2/P3）。
2. **MODE_APPEND 不支持**，明确抛出。
3. **大文件**：输出全量内存缓冲，>64 MB 拒绝；分块流式加密未实现。
4. **多进程**：`:remote` 进程各自持密钥可解密；跨进程锁/缓存一致性未做（AndroidX `PreferenceManager` 跨进程场景未覆盖）。
5. **SQLite/数据库**：按策略排除（`databases/*`），保持明文，符合 P1-D 排除设计。
6. 策略版本门控/热更新未做（P3）。
