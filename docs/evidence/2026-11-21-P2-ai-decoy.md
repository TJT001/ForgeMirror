# 2026-11-21 P2：语义诱饵（实验性）

## 目标

给 stub DEX 增加一批未被引用的安全域 decoy 类，用于研究自动化与
AI 辅助分析在语义噪声下的表现。该功能默认关闭，不属于 7 个核心保护层。

## 实现

| 位置 | 内容 |
|---|---|
| `data/ai_decoy.json` | 默认词表：包名、24 个类名、字段名与字符串；仅网络安全术语 |
| `formats/ai_decoy.py` | 校验词表，生成 Java 源码，`javac --release 11` 编译，打成 decoy jar |
| `protect.py` | `--ai-decoy` 时把 decoy jar 合并进 AAR 的 `classes.jar`，再走原有 d8 → stub DEX |
| `--ai-decoy-lexicon` | 替换词表；类名/字段名必须是合法 Java 标识符 |
| API / worker / 前端 | `ai_decoy` 选项透传，界面“语义诱饵”开关默认关闭 |

生成的类只包含 `static final String` 字段与 getter，没有静态初始化副作用，
运行时不加载、不引用。

## 验证

```text
ai_decoy_classes = 24
stub_dex_bytes   = 206,740   (S8 stub 上限 320 KB)
W_AI_DECOY: injected 24 unused decoy classes
classes.dex 含 Lcom/dexguard/decoy/symbols/{Ransomware,Keylogger,...};
```

Pixel 5 / API 30 安装运行：`bootstrap ok state=4`，探针全 0
（`native=T2XYZ6 java=T2XYZ6 dependency=7 dlopen=7 lockErr=0`）。

## 限制

1. 类名本身通常不足以触发模型的安全终止；该功能定位是增加 triage 噪音，
   不保证任何模型或扫描器的行为。
2. 安全域词汇可能触发应用商店、EDR 或杀软的启发式误报，默认关闭。
3. 依赖 JDK；无 JDK 时开启该选项会直接失败，不会静默跳过。
4. 词表刻意限制在网络安全术语，不内置违法或极端内容。
5. 与 7 个核心保护层独立，关闭后产物与之前一致。
