# 2026-11-13 P2 主线：S3–S8 可交付链路

## 范围

通用 S6（二进制 AXML 改写）、S3 默认策略、S5 壳 so 注入、S7 对齐签名、S8 闸门、CLI/worker 串接。

## 实现

| 阶段 | 实现 |
|---|---|
| S3 | `protect.py` 生成默认 SPK1 策略包；`ShieldPolicy` 运行时解析 |
| S5 | 从 shield AAR 注入四 ABI 的 `libshield_boot.so`/`libshield_core.so`；全 so 纳入完整性清单 |
| S6 | `formats/axml.py` 解析/改写/序列化 AndroidManifest.xml：替换 Application/Factory、注入 Provider 与 RecoveryActivity、按需 cleartext；替换业务 DEX 为 stub DEX |
| S7 | `zipalign -P 16` + debug 签名；so 以 ZIP_STORED 写入，满足 `extractNativeLibs=false` |
| S8 | `gate.py`：清单验签、全产物哈希、容器篡改、清单篡改、错误密钥负例 |
| 编排 | `forgemirror.cli protect`；worker 从 `build` 切换为 `protect`，任务产物变为最终 APK |

## 关键实现点

1. **AXML 保序改写**：保留原 string pool/资源映射与 chunk 顺序，新字符串追加；验证方式为 `aapt2 dump xmltree` + 设备启动。
2. **extractNativeLibs=false**：注入 so 必须 `ZIP_STORED` 且经 `zipalign -P 16`，否则安装报 `Failed to extract native libraries`。
3. **完整性覆盖**：`collect_artifacts(all_libs=True)` 将业务 so 一并纳入清单，壳运行时逐个校验。
4. **worker 结果**：数据库 `result_path` 指向最终 APK，不再是容器。

## 限制

1. **S4 规则包未实现**（P3）。
2. **S3 只有默认策略**：无客户策略上传、版本管理、热更新。
3. **S5 无客户 so 符号裁剪**；未做每 App 壳重建/参数注入。
4. **S6 仅覆盖常见 manifest**：不支持 styled string pool、split APK/AAB、动态特性；AXML 改写只在 harness 上验证。
5. **S7 仅 debug 签名**：无 HSM/客户本地签名模式；`signing_mode` 目前只记录不改变行为。
6. **S8 为最小闸门**：无 Unicorn/脱壳类红队同构器，无动态验证；负例覆盖容器/清单/密钥。
7. 默认仍内嵌开发密钥；`--no-key-asset` + 开发授权可替代。
8. worker 依赖本地已构建的 shield AAR；生产需固定产物分发。
