# 2026-11-13 P2 主线：S3–S8 可交付链路

## 范围

通用 S6（二进制 AXML 改写）、S3 默认策略、S5 业务 so 处理、S7 签名模式、S8 红队闸门、CLI/worker 串接。

## 实现

| 阶段 | 实现 |
|---|---|
| S3 | `protect.py` 生成默认 SPK1 策略包；`ShieldPolicy` 运行时解析 |
| S5 | 业务 so 的 ABI/ELF 架构校验；`llvm-strip --strip-unneeded` 符号裁剪；每构建写入 `app_id`/`build_salt`；注入四 ABI 壳 so；全部 so 纳入完整性清单 |
| S6 | `formats/axml.py` 解析/改写/序列化 AndroidManifest.xml：替换 Application/Factory、注入 Provider 与 RecoveryActivity、按需 cleartext；业务 DEX 换为 stub |
| S7 | `hsm`（开发期 debug 签名）/`customer_local`（仅 zipalign 的未签名包）；so 以 ZIP_STORED 写入 |
| S8 | `gate.py`：清单验签、全产物哈希、容器/清单篡改、错误密钥、A1–A4 |
| 编排 | `forgemirror.cli protect`；worker 从 `build` 切换为 `protect`，任务产物为最终 APK |

## S5/S7 验证

- `--signing-mode hsm`：4 个业务 so 被裁剪，签名后安装运行，JNI `Hello from C++` 正常。
- `--signing-mode customer_local`：输出未签名包，`apksigner verify` 拒绝（Missing MANIFEST.MF），`zipalign -P 16` 通过。
- ABI 错配：向 `lib/arm64-v8a` 放入 x86 ELF 后 `protect` 直接拒绝（`ELF x86 != dir arm64-v8a`）。
- API + worker 以 `signing_mode=hsm` 跑完整任务：4 秒成功，产物 16.7 MB，下载安装运行正常。

## 关键实现点

1. **AXML 保序改写**：保留原 string pool/资源映射与 chunk 顺序，新字符串追加；`aapt2 dump xmltree` 与设备启动双重验证。
2. **extractNativeLibs=false**：注入 so 必须 `ZIP_STORED` 且经 `zipalign -P 16`。
3. **完整性覆盖**：所有 so 纳入清单，壳运行时逐个校验。
4. **签名分流**：未签名包只做对齐；签名包使用 apksigner（开发期 debug keystore 代替 HSM）。

## 限制

1. **S4 规则包未实现**，A4 闸门为 inconclusive（P3）。
2. **S3 只有默认策略**：无客户策略上传、版本管理、热更新。
3. **S5 未做每 App 原生壳重建**；目前通过每构建 `app_id`/`build_salt` 与业务 so 裁剪做多样化。
4. **S7 无真实 HSM**：`hsm` 模式用 debug keystore 模拟，接口已分流。
5. **S6 仅覆盖常见 manifest**：styled string pool、split APK/AAB、动态特性未支持。
6. **S8 A1–A3 为静态/离线检查**，未接入 Unicorn 脱壳类工具。
7. 默认仍内嵌开发密钥；`--no-key-asset` + 开发授权可替代。
8. worker 依赖本地已构建的 shield AAR。
