## 范围

容器解密、`InMemoryDexClassLoader` 多 DEX 加载、业务组件从内存 classloader 解析、度量与恢复。

## 实现

| 模块 | 文件 |
|---|---|
| FDX2 Java 读取器 | `android/shield/src/main/java/dev/forgemirror/shield/ShieldContainer.java` |
| 内存 DEX 加载 | `ShieldRuntime.java`：HKDF/AES-GCM 解密 → `InMemoryDexClassLoader` |
| 业务类解析 | `ShieldApplication.java`、`ShieldAppComponentFactory.java` 使用内存 classloader |
| 运行时环境 | `ShieldArt.java`：SDK/ABI 日志；API 30 基线未需要 ART 适配器 |
| 受保护包构建 | `backend/pipeline/scripts/build_protected_demo.py` |
| S6 共用逻辑 | `backend/pipeline/forgemirror/s6.py` |
| 构建工具扩展 | `AndroidTools.d8`、`dex_jar` |

## 当前限制

1. **资源/布局类解析**：`LayoutInflater` 仍使用系统 classloader；含 AppCompat/ConstraintLayout 的 XML 布局会在 inflate 时找不到业务类。P1-C harness 使用框架 `Activity` + 纯代码 UI 验证 DEX 加载。Context/LayoutInflater 适配是 P2/P1-D 的前置项。
2. **业务 native 库**：`InMemoryDexClassLoader` 的 native library 路径不含应用 lib 目录，内存加载类里的 `System.loadLibrary("demo")` 会失败；P1-C harness 移除了该调用。需要自定义 classloader/native 路径或 ART 适配。
3. **JNI FindClass**：受 native 库限制，未验证从内存加载类发起 JNI 调用；同属上述适配项。
4. **DEX 规模**：当前 7 DEX；10+ DEX 压测尚未执行。
5. **解密位置**：P1-C 在 Java 中实现 FDX2 解密；原生 Core/BoringSSL 版本仍按设计推后到 P2。
6. **密钥**：`assets/shield/k_content.bin` 是开发密钥，随包分发，不能用于生产；P2 接 key-service/Keystore。
7. **清单算法**：仍是 P1-B 的 ECDSA P-256 原型；Ed25519 原生实现待 P2。
8. **通用 S6**：manifest 改写仍依赖 Gradle `shielded` 变体；任意 APK 的 AXML 重写未实现。
9. **API 26/27**：`appComponentFactory` 与内存加载适配未覆盖；当前基线 API 28+。
