## 命令

```bash
cd android && ./gradlew :app:assembleShielded
python3 backend/pipeline/scripts/build_shielded_demo.py \
  --apk android/app/build/outputs/apk/shielded/app-shielded.apk \
  --container artifacts/p1a-demo/container.fdx \
  --out artifacts/p1b/shielded.apk
adb install -r artifacts/p1b/shielded.apk
python3 backend/pipeline/scripts/tamper_shielded_demo.py \
  --apk artifacts/p1b/shielded.apk \
  --remove assets/shield/manifest.sig \
  --out artifacts/p1b/shielded-no-manifest.apk
```

## 当前限制

1. **S6 仍是演示形态**：manifest 改写由 Gradle `shielded` 变体完成，Python 只做资产注入、清单签名、对齐和签名。任意 APK 的二进制 AXML 重写尚未实现；`androguard` 4.1.4 只能读，`apktool` 未安装。通用 S6 是下一项。
2. **Application 代理限制**：`getApplication()` 返回 `ShieldApplication`，若业务代码强制转换为自己的 Application 类会失败。生产版需要生成原 Application 子类或寻找更透明的接管方式。
3. **签名算法原型偏差**：P1-B 使用 ECDSA P-256，因为 API 30 Java 提供者没有 Ed25519/EdDSA KeyFactory。Ed25519 仍是目标，P2 集成原生密码后端后切换。
4. **组件门控覆盖**：恢复期 Activity/Provider/Service/Receiver 已通过工厂替换为 stub；直接 Binder 调用、动态注册组件和已缓存组件仍待验证。
5. **DEX 未加密加载**：`container.fdx` 已注入并受清单保护，但 P1-B 仍加载 APK 内明文 DEX；解密/内存加载是 P1-C。
6. **清单覆盖范围**：当前签 `container.fdx`、`config.json`、`trusted_key.der` 和 libshield so；未签 `classes*.dex`。业务 DEX 的完整性由容器 TOC 覆盖。
7. **开发密钥**：签名私钥与容器密钥在 `artifacts/`，已 gitignore；生产走 key-service/HSM。
8. **API 26/27**：`appComponentFactory` 需要 API 28；API 26/27 的入口方案待单独实现。
