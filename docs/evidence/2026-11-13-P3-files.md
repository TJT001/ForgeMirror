# 2026-11-13 P3：文件保护扩展（随机访问 / 截断 / 重命名 / 跨进程）

## 范围

FILE-02 通配语义修正；FILE-05 普通文件随机访问原型（read/write/seek/setLength）；
加密文件重命名与跨进程读取验证。

## 实现

| 模块 | 内容 |
|---|---|
| `ShieldPolicy.java` | `**/` 按文档语义匹配零个或多个路径段；修正 `files/**/*.txt` 漏掉顶层文件的问题 |
| `ShieldRandomAccess.java` | 内存随机访问视图：打开时解密、`seek` / `read` / `write` / `setLength`、关闭时重新加密并原子替换；实现 `DataInput` / `DataOutput` |
| `ShieldFiles.java` | `openRandomAccess` 入口，未匹配策略的路径走明文回退 |
| `ShieldContextAdapter.java` / `ShieldStorage.java` | `openRandomAccessFile` 门面，按策略选择加密或明文 |
| `ShieldStorageFacade.java` | 业务侧调用点适配入口 |
| `HarnessStorage.java` / `HarnessRemoteService.java` | 随机写、截断、改名、跨进程读取的演示与校验 |

## 关键修复

原策略匹配把 `files/**/*.txt` 编译成 `^files/.*/[^/]*\.txt$`，要求 `files/` 后必须还有一层目录，
因此 `files/harness.txt` 从未命中，之前的文件保护实际一直走明文回退。按
`docs/formats/policy-v1.md` 的“`**` 匹配零个或多个路径段”修正为 `^files/(?:.*/)?[^/]*\.txt$`。

## 验证

### JVM 单测

```text
ShieldPolicyPatternTest: tests=4 failures=0 errors=0
- files/**/*.txt 命中 files/harness.txt 与 files/a/b/harness.txt
- shared_prefs/*.xml 不跨目录
- cache/** 命中整棵子树
- ? 只匹配单个非 / 字符
```

### 设备（Pixel 5 / API 30）

```text
readback prefs=true counter=2 file=true append=true ra=true

HarnessRemoteService: remote ra len=6 data=012XYZ
```

- 随机访问流程：写入 `0123456789` → `seek(3)` 写入 `XYZ` → `setLength(6)` → 内容 `012XYZ`；
- 关闭后改名 `harness_ra.txt` → `harness_ra_renamed.txt`，重新打开仍可解密；
- 远端 `:remote` 进程通过 facade 读取同一加密文件，得到 `012XYZ`，说明文件密钥与进程无关。

磁盘检查：

```text
harness.txt              67 B  （明文约 31 B + FMF1 头/标签）
harness_ra_renamed.txt   42 B  （明文 6 B + FMF1 头/标签）
harness_ra_renamed.txt 头 464d 4631 0100 0100  → FMF1
```

## 限制

1. 随机访问为**整文件内存视图**，上限 64 MiB；不是分块 AEAD，写入会重加密整个文件。
2. 未覆盖 `mmap/msync/munmap`、`truncate` 系统调用、文件锁、`dup` 与直接 syscall。
3. 未暴露 `getFD`/`getChannel`；`RandomAccessFile` 的 fd/channel 语义不可用。
4. 跨进程只验证了**顺序读取**；并发写、跨进程锁与一致性未实现。
5. 重命名通过 `File.renameTo` 验证，未做调用点自动改写。
6. SQLite/WAL 仍按策略排除，未做一致性验证。
7. 非策略路径走明文回退，内存视图会整体重写文件，保留原内容但不保留并发语义。
