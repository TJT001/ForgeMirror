# 2026-11-13 P3：文件保护扩展（随机访问 / 分块 AEAD / 重命名 / 跨进程）

## 范围

FILE-02 通配语义修正；FILE-05 随机访问（read/write/seek/setLength）；
FILE-07 分块 AEAD 文件格式 `FMF2`、原子迁移与崩溃恢复；重命名与跨进程读取。

## 实现

| 模块 | 内容 |
|---|---|
| `ShieldPolicy.java` | `**/` 按文档语义匹配零个或多个路径段；修正 `files/**/*.txt` 漏掉顶层文件的问题 |
| `ShieldChunkStore.java` | `FMF2` 分块 AEAD：72 字节头、固定块槽位、每块独立 nonce/tag、脏块重写、临时文件 + fsync + 原子替换；隐藏锁文件上的共享/排他 `FileLock` 覆盖跨进程读写 |
| `ShieldRandomAccess.java` | 加密文件随机访问视图；`FMF2` 走分块路径，`FMF1`/明文读取后写时迁移到 `FMF2`；实现 `DataInput` / `DataOutput`；`getFD`/`getChannel` 返回只读明文 memfd 快照 |
| `formats/file.py` | host 侧 FMF1/FMF2 编解码与迁移工具：FMF1 解密、FMF2 编码/校验、atomic 迁移 |
| `ShieldFiles.java` | `openRandomAccess` 入口，未匹配策略的路径走明文回退 |
| `ShieldContextAdapter.java` / `ShieldStorage.java` | `openRandomAccessFile` 门面，按策略选择加密或明文 |
| `ShieldStorageFacade.java` | 业务侧调用点适配入口 |
| `HarnessStorage.java` / `HarnessRemoteService.java` | 创建、随机改写、截断、改名、跨进程读取 |
| `docs/formats/file-v2.md` | `FMF2` 布局与密码契约 |

## 关键修复

1. **策略通配**：原实现把 `files/**/*.txt` 编译成 `^files/.*/[^/]*\.txt$`，要求 `files/` 后必须还有一层目录，
   因此 `files/harness.txt` 从未命中，之前的文件保护实际一直走明文回退。按
   `docs/formats/policy-v1.md` 的“`**` 匹配零个或多个路径段”修正为 `^files/(?:.*/)?[^/]*\.txt$`。
2. **AAD 与长度变化**：分块 AAD 含该块明文长度，扩展/截断会改变末块的 AAD。持久化时用
   `persistedLength` 解密旧块、用新长度重新加密受影响的末块，其余未修改块直接复制原始密文。
3. **截断后再扩展**：`zeroFrom` 记录本次会话内截断位置；扩展后该位置之后的旧持久块按零处理，
   防止已截断的明文被重新读出。

### 设备（Pixel 5 / API 30）

```text
readback prefs=true counter=1 file=true append=true ra=true mmap=true

HarnessRemoteService: remote ra len=6 data=0Q2XYZ
HarnessStorage: lock held name=harness_lock.txt
HarnessRemoteService: lock probe waitMs=1478 len=2
```

`getFD`/`getChannel` 返回只读明文 memfd 快照；`FileChannel.map` 可读，
但通过快照写入不会回写加密文件。跨进程写锁通过隐藏锁文件上的排他 `FileLock`
实现，远端进程等待约 1.5 秒后拿到锁，最终长度 2（两侧写入都保留）。

流程：

1. 新建 `harness_ra.txt`，写入 `0123456789` → `seek(3)` 写 `XYZ` → `setLength(6)`，关闭后为 `FMF2`；
2. 改名为 `harness_ra_renamed.txt`；
3. 重新以 `rw` 打开已存在的 `FMF2`，`seek(1)` 写入 `Q`，关闭后内容为 `0Q2XYZ`；
4. 主进程读回 `ra=true`；远端 `:remote` 进程读取同一加密文件得到 `0Q2XYZ`。

磁盘检查：

```text
harness_ra_renamed.txt  65636 B = 72 字节头 + 1 块（65536 + 12 nonce + 16 tag）
magic                   464d 4632 0200 0100 → FMF2
```

## 限制

1. 未覆盖原生 `mmap/msync/munmap`、`dup` 与直接 syscall；`getFD`/`getChannel` 返回的是
   只读明文 memfd 快照，通过快照的写入不会回写加密文件。
2. 跨进程锁已覆盖门面打开的文件；同一进程重复打开同一文件会因 `OverlappingFileLockException`
   失败。未实现目录 fsync 与掉电原子性形式化证明。
3. 脏块保存在内存；大量随机写会占用与脏数据等量的内存。
4. 旧 `FMF1`/明文迁移仍是整文件读入内存后重写，受 64 MiB 门面上限约束；host 侧迁移工具已提供。
5. SQLite/WAL 仍按策略排除；未做一致性验证。
6. 文件锁是建议锁，绕过壳直接写文件的原生代码不受约束。
