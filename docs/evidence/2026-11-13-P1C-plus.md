# 2026-11-13 P1-C+ 兼容层执行记录

## 范围

资源/LayoutInflater classloader、AppCompat/XML 页面、业务 native 库、JNI 符号、Application/多进程回归。

## 实现

| 项 | 实现 |
|---|---|
| Context classloader | `ShieldContextWrapper` 保留资源委托，覆盖 `getClassLoader()` 返回内存加载器 |
| Activity 适配 | `ShieldRuntime.adaptActivity` 在 `onActivityPreCreated` 替换 `ContextWrapper.mBase` |
| 生命周期注册 | `ShieldApplication` 注册 `ActivityLifecycleCallbacks`，API 29+ |
| 业务页面 | `MainActivity` 恢复 `AppCompatActivity` + `ActivityMainBinding` XML 布局 |
| 业务 native | `MainActivity` 用 `System.load(<sourceDir>!/lib/<abi>/libdemo.so)` |
| 环境日志 | `ShieldArt` 输出 SDK/ABI |

## 失败与取舍

1. **`LayoutInflater.mClassLoader` 不存在**：API 30 上该字段不可用；改为替换 Activity 的 `mBase`，让 `LayoutInflater`/AppCompat 通过 `getClassLoader()` 拿到内存加载器。
2. **`onActivityPreCreated` 前 window 为空**：工厂返回时 `getLayoutInflater()` 不可用；改在 `onActivityPreCreated`（API 29+）适配。
3. **`DexPathList.addNativePath` / `nativeLibraryPathElements`**：能看到字段和 `addNativePath`，但对 `InMemoryDexClassLoader.findLibrary` 不生效，`findLibrary` 仍为 null。
4. **壳类 shim 加载 native 不可行**：从 `ShieldRuntime.loadLibrary` 调 `System.load` 会把 so 关联到 stub classloader，内存类 JNI 查不到符号。
5. **业务类自己调 `System.load(APK 内绝对路径)` 可行**：当前 harness 采用该路径验证。通用应用需要在构建期把 `System.loadLibrary` 调用改写为 `System.load(sourceDir + "!/lib/<abi>/libX.so")`，这属于 S5/S6 的 DEX 改写任务。

## 仍待解决

1. **通用 native 改写**：构建期 DEX 改写 `System.loadLibrary`/`System.load` 调用点，或实现带 library path 的自定义 classloader。
2. **API 26–28**：`onActivityPreCreated` 不存在，需要 Instrumentation/ART 适配或其他 hook。
3. **Application 语义**：`getApplication()` 仍返回 `ShieldApplication`，强制转换为业务 Application 会失败；需要生成原 Application 子类。
4. **DEX 规模**：7 DEX；10+ DEX 与真实第三方应用未压测。
5. **通用 S6**：仍依赖 Gradle `shielded` 变体；任意 APK 的 AXML 重写未实现。
6. **密码/密钥**：Java 解密、开发密钥随包、ECDSA 原型；原生 Core/Ed25519 与 key-service 在 P2。
