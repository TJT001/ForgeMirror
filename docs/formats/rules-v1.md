## 1. 二进制布局

所有整数为 little-endian。

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 4 | `magic` | ASCII `PKR1` |
| 4 | 2 | `version` | `1` |
| 6 | 2 | `min_shell_version` | 编码为 `major*10000 + minor*100 + patch` |
| 8 | 1 | `cipher` | `1` = AES-256-GCM |
| 9 | 1 | `reserved` | `0` |
| 10 | 12 | `nonce` | 随机 |
| 22 | 4 | `plaintext_len` | 编译后规则载荷长度 |
| 26 | `plaintext_len + 16` | `ciphertext` | 密文 + GCM tag |
| 末尾 | 64 | `signature` | Ed25519 |

签名覆盖从偏移 0 到 `ciphertext` 结束的全部字节。

## 2. 密码契约

| 项 | 值 |
|---|---|
| 密钥 | `HKDF(K_content, salt=build_id, info="FM/rules/v1")` |
| AEAD | AES-256-GCM |
| AAD | 头部前 26 字节 |
| 签名 | Ed25519，公钥与清单一致 |

## 3. 载荷

P0 只冻结容器头，载荷格式在 P3 定义。约束：

- 载荷是编译后的规则数据，不是 `.yar` 源码；
- 规则来源、特征值和许可逐项记录，研究侧九条规则不直接作为产品资产；
- 解析器必须有长度、数量和资源上限；
- 解析失败、签名失败或版本不满足时保留旧规则，不部分加载。
