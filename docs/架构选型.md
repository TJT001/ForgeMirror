# 平台架构与技术选型

日期：2026-11-12。架构基线；具体版本在初始化时验证并锁定。目前仅 Android 模板已创建。

| 层 | 选型 | 职责 |
|---|---|---|
| 前端 | Vue 3、TypeScript、Vite、Element Plus、Vue Router、Pinia | 上传、配置、任务、报告下载；fetch 请求，SSE 进度与日志，轮询兜底 |
| API | Go + Gin | 单体组织应用、方案、任务、产物、授权、事件 |
| 数据 | PostgreSQL + pgx + SQL migration | 数据持久化、初期任务队列；sqlc 按规模引入 |
| 执行 | Python + uv + Pydantic + Typer + pytest | 独立 worker、可本地执行的流水线 |
| DEX 工具 | Java + dexlib2 | Python 调用的分析和改写工具 |
| Android | Java + C++17 + NDK/CMake | app 实验宿主、待建 shield library；原生模块对外为 C ABI |
| 存储 | 本地文件系统与可替换接口 | 输入、工作目录、产物和报告 |
| 部署 | Docker Compose | 前端、API、worker、数据库；设备验证在宿主运行 |

## 目录和边界

只保留 frontend、backend、android、docs 四个顶层目录。backend 按需建立 cmd、internal、pipeline、migrations、tests；Python 和 Java 工具归 pipeline，向量归 tests。Android 使用 Studio 结构，后续新增 shield。授权和事件先为单体内部模块，不拆微服务，不引入 Redis。

## 任务闭环

前端上传 → Go 创建任务 → Python worker 事务领取 → 流水线调用 Java/Android 工具 → 验证产物 → API 提供报告与下载。API 不同步等待构建。任务表提供 queued/running/succeeded/failed/canceled 状态、租约、心跳、重试上限；终态更新校验 worker 所有权，失败重试按 attempt 隔离。

每任务独立目录和进程组，参数结构化，命令使用参数数组；限制资源、并发、超时、ZIP 展开和文件大小，支持取消和清理。客户端只能传文件 ID，不能提交任意命令或本地路径；任务与下载按归属授权，产物验证后原子发布。

worker 输出版本化 JSON 事件（task_id、attempt、sequence、stage、status、progress、reason_code），日志单独保存且有上限；API 通过 SSE 转发，支持恢复或轮询，不解析控制台文本判定成功。

## 构建和运行时

Python 提供 inspect/protect/verify CLI，本地与 worker 共用。壳构建为独立 Gradle 步骤，记录版本和哈希；常规流水线消费已构建 AAR/so，每 App 重建显式触发壳构建。Java 工具协议独立版本化。

Android Java 负责入口、组件和反射，C++17 负责原生机制，C ABI 不传 STL/异常。保留现有 minSdk 26、compileSdk/targetSdk 37，固定 NDK 和运行 JDK；API 26/27 入口与 API 28+ 分开验证。Pixel 5/API 30 为首个基线，ART/APEX/ABI 按实测选择适配器。ByteHook、ShadowHook、BoringSSL、YARA 按设计 §18 验证，不默认已支持。

## 扩展及实施

机制声明 id、版本、平台/ABI、依赖与冲突、配置 schema、构建步骤、运行时能力和测试；Python 注册表只执行随项目发布的可信代码。

P0 验证现有 JNI 与格式草案；P1 实现容器、接管、完整 DEX、文件四原型，必须包含开发授权，并建立最小前后端/worker；P2 完成 Web 上传到下载闭环、生产授权、签名、恢复与 CI；P3 规则和文件扩展；P4 扩大系统和发布范围。供应链从首次引入依赖即开始。
